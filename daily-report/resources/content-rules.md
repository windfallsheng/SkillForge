# 内容规则

## 输出内容与数据来源
- 三段结构：今日任务进度（3-6 点）/ 明日计划 / 风险阻塞点
- 任务点格式：1、任务描述（量化数据：文件数/行数/提交次数）- 进度XX% - 用时XH
- 任务来源（默认）：各仓库当日 git 提交自动聚合 + 本次会话中用户已提及/口述的工作内容 + 用户口头补充，全部合并去重；仅当用户明确说"只整理这段文字/只按这段"时才忽略 git 与会话上下文、只用指定文字（见「纯文字整理模式」）
- 「明日计划」取材双通道：①用户口述/文字补充的计划（优先并入）；②一次生成连续多天日报时（本次批量生成中后面日期的日报，或 reports 目录中已存在的后续日报），从后一天日报的「今日任务进度」中抽取任务作为当天「明日计划」（抽取数量灵活、不设死上限：后续完成任务多且连续性强时可多抽至 4-5 条，少则抽 1-2 条，与后续日报内容形成呼应即可），描述改写为计划语气（完成态改进行态：如「完成 XX 重构」→「推进 XX 重构」「继续 XX 开发」，去掉量化数据/进度/用时）；批量多天时优先保证跨天连续性：抽取时尽量让当天「明日计划」与后一天「今日任务进度」形成「计划→完成」的同主题承接链（如 11.05 计划「推进底部导航重构」→ 11.06 完成「完成底部导航重构」，同一条工作线前后呼应，跨天任务尽量串成连续的工作链）；批量中最后一天无后续日报时，该段按口述或「暂无」处理
- 量化数据取自 git --stat（文件数、增删行数）；用时为合理估算（git 不记录耗时，估算值注明"约"，可口头修正）
- 数据收集范围（按当前系统自动选择，另一系统的仓库自动跳过）：macOS = NearCast / nearcast-server / nearcast-go / nearcast-admin / SmartCanteenConsumerMachineApp / TrustPay 共 6 个仓库；Windows = srf-app / srf-manage / srf-operation / srf-service / srf-web-user / srf-web-operation / srf-web-wx / srf-web-h5-teacher / srf-web-uop / Spec-Core-Smart-Canteen 共 10 个仓库；无当日提交的仓库不写入
- HTML 版为参考图式深蓝面板卡片美化样式（实心深蓝卡片 + 细密水平条纹 + 上下边缘高光线 + 左缘节色条，保留 ask 同款发光动效）：顶部「一键复制」按钮（复制纯文本版）+ TL;DR 摘要行、「今日任务进度」标题右侧带目标日期徽章 + 任务进度节内当日节奏条（上午/下午/晚上时段条，hover 显示时段提交明细）+ 节奏条下量化指标行（提交次数/涉及文件数/代码行数）+ 进度条终点圆点与流星扫描填充 + 液态玻璃卡片（@supports 兜底）+ CRT 扫描光带 + 全页 3D 微倾斜（±0.75°）、页脚署名 GENERATED BY SPECCORE TEAM（日期动态跟随目标日期），并随 FORMATS 默认落一张内容区截图 content-png（卡片整体 + 四周留白 + 日期徽章）

## 用户补充任务

用户调用时可能口头追加任务（如"再补充一下：上午改了角标接口，下午跟测试联调了"），按以下规则处理：

- **触发**：话术含"补充/加上/还有/另外/以及/对了"等追加词，或直接口述任务内容（说"整理成日报/只整理这段文字/只按这段/不用 git"时走「纯文字整理模式」，不是追加）
- **分段**：补充内容带分段词时按段并入——"明日计划/计划：xxx"→ 明日计划段；"风险/阻塞：xxx"→ 风险阻塞点段（说"风险暂无/无风险"→ 风险段写「暂无」）；不带分段词默认并入"今日任务进度"
- **拆条**：按语义主题拆分，一个主题一条；拆分信号：时间词（上午/下午/晚上）、追加连接词、分号顿号列举、数字列举（1、2、3）
- **润色**：口语整理为规范任务描述（动词开头、说清对象与结果）；用户未给量化数据时，优先从 git 提交补文件数/行数，无记录则省略量化、只写进度与用时（估算值注明"约"）
- **去重**：与 git 聚合任务合并时，同一件事只保留一条
- **格式**：与 git 聚合条目同格式，接在"今日任务进度"下继续编号

## 纯文字整理模式（用户贴一段文字，无 git 提交）

用户调用时直接贴一段文字并说"整理成日报/根据这段生成日报"（可能不是开发岗位，没有任何 git 提交），按以下规则处理：

- **触发**：话术含"整理/根据这段/以下内容/帮我梳理"等 + 附了一段多句文字/图片/文件，或明说"只整理这段文字/只按这段/不用 git/别收集 git"（与"写日报 + 补充一下"的区别：文字/图片/文件是唯一主源、跳过 git 与会话上下文，不是追加）
- **数据来源**：用户文字/图片/文件为主源，**跳过 git 收集**（不跑 git 命令）且忽略本次会话其它工作内容；图片用 Read 视觉理解提取图中文字信息，md/txt 直接读文本，docx/pdf 优先尝试 pandoc 转文本（无 pandoc 则请用户粘贴文字）；用户是开发且内容提到代码相关工作时，可仍收集 git 用于补量化数据
- **三段归类**（用户文字没按段写明时用信号词归类）：
  - 含"明天/明日/接下来/计划/准备/打算/将要/待办" → 明日计划
  - 含"风险/阻塞/问题/卡住/困难/待定/依赖/遗留" → 风险阻塞点
  - 其余 → 今日任务进度；全段无任何信号词 → 全部归入今日任务进度
  - 用户已明确分段（"今日完成：A；明日计划：B；风险：C"）→ 按用户分段，不猜
- **拆条**：按语义主题拆分，一个主题一条；拆分信号：时间词（上午/下午/晚上）、连接词（还有/另外/以及）、分号顿号列举、数字列举（1、2、3）、换行/段落边界
- **润色**：口语整理为规范任务描述（动词开头、说清对象与结果），每点 20-40 字
- **量化数据**：无 git 提交 → 不写文件数/行数/提交次数；格式退化为「1、任务描述 - 进度XX% - 用时XH」
- **进度与用时**：文字没给进度时，完成任务默认 100%、计划默认 0%；用时/预估用时仅在用户文字给出时才写，没给就省略（不瞎编估算值）
- **风险阻塞点**：只列描述
- **日期/落盘/HTML**：与常规流程一致（默认今天、md/txt/html 三文件 + 内容区截图落盘、html 自动打开）

## 输出格式

```markdown
# 今日日报 - YYYYMMDD

> 生成时间：YYYY-MM-DD HH:MM:SS

## 今日任务进度
1、任务描述（量化数据：文件数/行数/提交次数）- 进度XX% - 用时XH

## 明日计划
1、任务描述 - 进度XX% - 预估用时XH

## 风险阻塞点
- 阻塞描述
```

## 规则

- 任务进度 3-6 点，每点 20-40 字；序号用中文顿号（1、2、）
- 聚合后任务数超上限（6 点）时，同类小任务合并压缩到上限内；用户说「精简点/太长了」→ 条目数取下限、每点压缩到 20 字左右；说「详细点」→ 条目数取上限、每点写足 40 字
- 三段兜底：任务进度默认 100%；任务进度/明日计划/风险阻塞点无任何内容时该段写「暂无」（默认聚合时明日计划无 git 来源，用户没给计划就写「暂无」）
- 计划每点带进度百分比与预估用时
- 风险阻塞点三环结构：问题+影响+建议，不写进度用时
- 用时单位：XH（小时），估算值注明"约"
- 文字风格约束：①明日计划用计划态陈述句，动词取「推进/启动/开展/跟进/梳理/筹备/验证/排查/联调」等计划态词，禁用完成态词（完成/搞定/已实现/做完），可带「计划/预计/拟」字样（不必每条都有），句式「动词+对象+目标范围」（如「推进底部导航重构，完成主流程交互调整」），禁祈使句（「去做 xx」）与口语（「把 xx 弄一下/搞搞」）；②完成任务用动词开头的完成态陈述句（完成/修复/优化/重构/开发/实现/接入/升级/排查/联调/上线），说清对象与结果（如「完成底部导航重构」）；③风险阻塞点三环结构：问题+影响+建议（问题客观陈述、影响说明后果、建议给出可执行对策），不写抱怨与情绪话；④全文通用：不用第一人称「我」、不用口语语气词（啦/啊/吧/哈/哦/呢）、不用 emoji、不用口语形容词（差不多/还行/基本上/搞不定/一堆）；用户口述/补充的口语内容一律先润色为规范书面语再写入（「上午改了角标接口」→「完成角标接口改造」），量化数据（文件数/行数/进度/用时）格式不变
- 报告标题下输出生成时间，精确到时分秒（YYYY-MM-DD HH:MM:SS）
- 生成报告时，对话中先输出简要「使用提示」（几条速览 + 完整说明引用）再输出报告正文，固定条目：
  - 默认生成今天；「昨天的日报 / 上周三的日报 / 10月20号的日报」指定日期
  - 「补充一下：xxx」追加任务（「明日计划：/风险：」分段词自动归段）；贴文字/发图片/给文件「整理成日报」默认直接生成，说「先看看效果」→ 确认后再落盘
  - 默认聚合 git 提交 + 本次会话已提的工作内容；说「只整理这段文字」→ 仅用该文字
  - 「写到桌面 / 不落盘 / 只要 md / 只要截图 / 这次不截图 / 别开浏览器 / 保留之前的」临时控制落盘；「这次按 xxx 模板来」临时换模板
  - 生成完成后在对话中告知本次落盘的文件完整路径清单（目录 + 各文件名，Windows 用反斜杠）
  - 默认配置长期生效：改 skill 文件顶部「默认配置」节（DISK/FORMATS/DIR/OPEN_HTML/TEMPLATE/CONFIRM）
  - 📖 完整使用说明：问「日报怎么用」
- 默认聚合来源：git 提交 + 本次会话中用户已提及/口述的工作内容全部合并去重；仅当用户明确说"只整理这段文字/只按这段"时，才只用指定文字、忽略其它来源
- 目录名 = 目标日期（解析出的报告日期），不是生成时刻：整理"昨天的日报"时目录用昨天日期、git 收集范围也是昨天；标题中的 YYYYMMDD 同为该目标日期
- 纯文字整理模式：用户贴一段文字/发图片/给文件说"整理成日报/只按这段"时跳过 git 收集与会话上下文，内容为主源（图片 Read 视觉提取、md/txt 直接读、docx/pdf 优先 pandoc 转文本）；按信号词自动三段归类（用户已分段则按用户分段）；无量化数据不写文件数/行数，进度默认完成 100%/计划 0%，用时用户没给就省略；CONFIRM: never 默认直接生成落盘不确认，CONFIRM: text/always 或用户说"先看看效果"时先出整理效果、用户说"可以/确认/落盘"后再落盘，说"改一下 xxx"按意见修改后重新确认，说"不用确认/直接落盘"跳过确认（CONFIRM 配置控制，临时口头要求优先）
- 模板优先级：用户临时口头指定的模板 > 顶部 TEMPLATE 配置（custom 用「📝 自定义模板」节结构，default 用内置三段式）；自定义模板只改段名/段数/条目格式，其余规范（中文顿号序号、生成时间、落盘、HTML 样式）不变
- 日期优先按自然语言解析（如"昨天的日报"、"上周三的日报"）；显式参数 `/daily-report [YYYYMMDD] [md|txt|html]` 等价于自然语言，日期缺省为今天
- 跨系统兼容：执行时先检测当前系统（macOS/Windows），所有路径、命令、浏览器均按系统分支取值（DIR auto→DIR_MAC/DIR_WIN、仓库表对应路径列、Chrome/Edge 路径、open/Start-Process、桌面/回退目录）；禁止假设单一系统
- 落盘行为读取顶部「默认配置」（DISK/FORMATS/DIR/OPEN_HTML/TEMPLATE/CONFIRM）；优先级：用户临时口头要求（不落盘/写到桌面/只要 md/只要内容区截图/只要截图/这次不截图/别开浏览器/临时换模板/先看看效果/不用确认等，仅当次生效）> 顶部默认配置；DIR（按系统解析）目录/盘符不存在时回退用户主目录 reports（macOS=~/reports、Windows=%USERPROFILE%\reports）；同日期重复生成覆盖原文件，用户说"保留之前的"则时间戳另存
