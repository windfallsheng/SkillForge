# 一页纸海报（one-pager）

一句话主题进 → 一屏海报出：内容提炼 → HTML 海报（8 套布局 × 5 套主题可切换、纵向一屏、打印友好）→ 可选 PNG 截图。

## 生成流程

0. **读用户配置**（TEMPLATE/THEME/DIR/OPEN_HTML/SHOT/ASPECT）→ 先 Read 同目录 `user-config.md`
1. **内容提炼**（主题句 → 标题/金句/要点块，问清再动）→ 读 `resources/content.md`
2. **生成 HTML**（先 Read reference.html 骨架替换数据）→ 读 `resources/generate.md` 与 `resources/html-rules.md` 两份
2.5 **交付前自检**（硬门禁不可跳过）：HTML 文件写好后——
   - 挂 pageerror 监听用 Chrome headless 访问页面（零容忍报错）→ 截全页 PNG Read 自查：标题/金句/要点块齐全、一屏内无溢出、无豆腐块缺字
   - SHOT: true 时用 Chrome headless 带 `?shot` 参数截 PNG 落盘（同海报文件名 .png）
   - 任何报错或视觉问题：修 HTML → 重检；全绿才进第 3 步
3. **使用咨询**（用户只问「一页纸海报怎么用」等用法、未要求生成）→ 读 `resources/usage-guide.md`，将其内容原样输出（首行标题改为「一页纸海报使用指南」），不提炼内容、不落盘、不开浏览器

## ⚙️ 配置与自定义

**执行本 skill 前必须先 Read 同目录 `user-config.md`**：默认配置（TEMPLATE/THEME/DIR/OPEN_HTML/SHOT/ASPECT）都在该文件中，以它为准。升级技能时 user-config.md 不会被覆盖，你的修改永久保留；官方更新配置时另存 `user-config.md.upstream` 对照文件，可按需手动合并新配置点。

- **TEMPLATE**：海报布局模板，classic 经典舞台（默认，徽章+渐变巨字+三列要点卡）/ minimal 极简留白（瑞士平面，衬线巨字+编号竖排要点）/ magazine 杂志社论（刊头通栏线+左文右栏+首字下沉金句）/ hero 巨幕大字（电影海报式巨型关键词+底部要点横条）/ timeline 时间叙事（中央竖线+要点左右交替卡片）/ grid 卡片栅格（2×2 大圆角卡片+描边编号角标）/ dashboard 数据仪表（KPI 环形图+要点进度条）/ brutalist 新粗野（撞色块+4px 粗框+硬阴影）；生成时写 `<html data-template="TEMPLATE值">` 定默认，页面右下角模板坞八标签随点随换、与五主题正交组合出 40 种版式（localStorage 记忆，键按页内嵌唯一 ID 隔离、多份产物互不串台、改名/移动目录记忆不丢；生成时头部写 `<meta name="poster-id" content="<UUID>">`，每次 crypto.randomUUID() 生成标准 UUID v4（8-4-4-4-12 十六进制，禁止手写变体、禁止沿用占位与旧值）；落盘写文件前顺扫落盘目录下本技能命名的 html，读各文件 id meta 查重，撞号重掷至不重复）
- **THEME**：海报主题，tech 深蓝科技（默认）/ biz 浅色商务 / mono IDEA 黑亮 / light IDEA 白亮 / warm 温暖渐变；生成时写 `<html data-theme="THEME值">` 定默认，页面右下角主题坞五色点随点随换（记忆与隔离机制同 TEMPLATE）

## 配置版本机制（升级保护）

本 skill 当前配置版本为 `2`（对应 user-config.md 中的 `CONFIG_VERSION`）。执行时若发现 user-config.md 的 CONFIG_VERSION 与本节声明不一致：

1. 先将旧 user-config.md 备份为 `user-config.md.bak-<时间戳>`（同目录，绝不删除旧值）
2. 按本节「配置升级规则」迁移字段：新增字段补默认值、改名字段按映射改写、删除字段的值保留在备份中并在对话提示用户手动确认
3. 更新 CONFIG_VERSION 为当前版本
4. 对话中明确告知用户「检测到配置版本从 X 升级到 Y，旧配置已备份至 <路径>」

迁移规则（v1 → v2）：新增 `TEMPLATE` 字段，默认 `classic`，其余字段不变。

升级本 skill 时，配置结构如有变化必须同步更新本节的当前版本号与迁移说明；禁止在未声明版本变更的情况下静默修改配置语义。

## 🔧 报修处理流程（用户报页面问题时）

用户说「这个页面效果不对 / 布局乱了 / 有 UI 问题 / 样式错了 / 交互坏了」（常附截图或指出具体现象）→ 按以下流程处理，不以「重新生成一份」敷衍：

1. **立标准**：先 Read 本 skill 目录 `resources/reference.html`——它就是设计标准答案（布局/配色/交互全在代码里）
2. **找问题**：Read 用户那份问题 html 文件，与 reference 逐处比对（结构顺序 / CSS 变量 / 关键类名 / 交互 JS），定位跑偏处；用户给了截图则按截图现象反查
3. **修复**：以 reference 为准修复那份 html（只修跑偏处，不动正确内容；reference 与 html 不一致时以 reference 为准）
4. **自证**：Chrome headless 访问修复后页面截全页 PNG，Read 自查修复点恢复标准效果
5. **汇报**：一句话说清问题根因 + 修复了什么 + 附截图；若根因在 reference.html 自身，顺修 reference.html 对应处并在汇报中说明「参考模板已同步修正」


## 产物升级（回炉）

生成 HTML 时头部写版本戳 `<meta name="sf-template" content="one-pager@3">`（模板升级时递增 @N 并同步 reference.html 与本文档）。用户说「升级旧海报/回炉」时：扫落盘目录读版本戳筛旧版（无版本戳或缺少 `<meta name="poster-id">` 稳定 ID 的产物视为 v0 最旧版，一并进清单）→ 列清单（文件/旧版本）→ AskUserQuestion 选全部或部分 → 逐份升级：浅升级（仅 CSS/JS 变化）对旧页替换 `<style>` 块与交互脚本、正文原样保留；深升级（DOM 结构变化）从同目录 md 底稿按当前 reference.html 重建，先备份旧版 `.bak-时间戳`，重建必须沿用原页 poster-id meta 值（换 ID = 模板/主题记忆失联）→ 报告三段式：✅ 已升级清单 / ⚠️ 手改保留说明 / 🟡 失败项原因。模板改动分级：业务改动、数据格式改动、页面改动任一发生即模板升级，版本戳 +1 并同步 reference.html 与本文档；纯措辞润色不 bump。每次生成 HTML 时顺扫落盘目录读版本戳：发现旧版产物主动告知用户「说『把我旧海报都升级成新样式』即可一键升级」。

## 规则速览

- 一屏原则：海报纵向一屏展示（内容自适应缩放不滚动出第二屏）；要点块 3-5 条，每条 15-30 字，禁止长篇大论
- 内容问清再动：主题句不够明确时先与用户确认标题/要点口径，不猜
- 零侵权：系统字体栈、禁止 CDN/外链资源，页面离线双击可开；页脚署名固定 GENERATED BY AI TEAM
- 八模板 × 五主题 = 40 种版式正交组合；模板管布局骨架、主题管配色变量，生成时按 TEMPLATE/THEME 配置定默认，用户可页面右下角坞随手切换
- 落盘完成后对话必须报告落盘位置：完整路径清单（html + 可选 png），并注明 html 是否已在浏览器打开
