# 发版说明生成器使用指南

## 能做什么

把 git 两个版本标签之间的提交，变成一份**人能读的发版说明**——自动分类归纳（新功能/修复/文档/优化），按用户视角改写（做了什么 + 带来什么），产出中英双语 RELEASE 文件与 CHANGELOG 条目，并附 npm 发布前自检清单。

## 怎么用

1. 说「**写发版说明**」或「**生成 release notes**」→ 我先读配置、收集 git 提交
2. 我可顺口补充口径：「从 v1.0.7 到 v1.0.8」「只看最近两周」「聚焦 CLI 与文档」
3. 口述本期要点（改了什么大方向）→ 与提交合并归纳
4. 产出：RELEASE-{tag}.md（中英双语）+ CHANGELOG 条目 + 发布自检清单，落盘后报路径

## 可改配置（user-config.md）

- `REPO`：仓库根目录（默认当前目录向上探测）
- `LANG`：zh / en / both
- `CHANGELOG_FILE` / `REL_DIR`：落盘位置
- `STATS`：是否附提交统计
- `SCOPE_HINT`：发版说明聚焦主题

## 使用提示

- 没有 tag 时我会先问口径，不擅自假设
- 每个版本发版前顺手跑一遍，CHANGELOG 永不欠账
