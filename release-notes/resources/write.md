# 分类与改写（阶段 2-3）

## 分类规则

| 类型 | 归属 | 说明 |
|:---|:---|:---|
| feat | 🚀 新功能 | 用户可感知的新能力 |
| fix | 🐛 修复 | bug 修复，说明修了什么、影响什么场景 |
| docs | 📝 文档 | 文档增改（含示例、指引页） |
| perf | ⚡ 优化 | 性能 / 体验优化 |
| refactor | ♻️ 重构 | 结构改造（对外行为不变） |
| breaking | 💥 破坏性变更 | 单独置顶，必须写明迁移方式 |
| chore | 杂项 | 依赖 / 构建 / 琐碎项，一句话带过或省略 |

## 改写纪律（用户视角）

- 每条「**做了什么 + 带来什么**」：如「新增 skill-forge update 命令：升级时自动备份用户配置并三选一，用户改动不再被覆盖」
- 同类提交合并为一条；每类 1-5 条；无价值的 chore 直接忽略
- 禁止照抄 commit message 原文当说明；禁止流水账式逐条罗列
- SCOPE_HINT 非空时聚焦该主题归纳，其余一句话带过

## 落盘

1. **RELEASE-{tag}.md**（REL_DIR 下，无 tag 用 RELEASE-{日期}.md）：顶部「版本 + 日期 + 一句话主题」，正文按分类列条目，底部附统计（STATS: true 时）
2. **CHANGELOG 条目**：在 CHANGELOG_FILE 顶部（现有版本标题行上方）插入「## {version}（{日期}）」+ 条目；LANG: both 时同步生成 / 更新 CHANGELOG.en.md
3. 双语时两份排版结构一致，术语对照一致；对话中照常输出发版说明正文
4. **落盘完成后对话报告落盘位置**：完整路径清单（RELEASE 文件 + CHANGELOG 文件），并注明是否已插入 CHANGELOG
