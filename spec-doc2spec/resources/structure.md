# 目录组织与落盘

## 默认输出结构

```
{源目录}/{文档名}-spec/          ← OUTPUT_DIR=auto 默认；OUTPUT_DIR 写绝对路径时以其为产物根目录，其下仍建 {文档名}-spec/ 子目录（说「直接放这个目录」才平铺）
├── README.md                    ← 索引：源文档、转换时间、章节清单、校对记录摘要
├── 00-converted.md              ← Pandoc 机械底稿（AI 已校对修正版，保留溯源）
├── 00-plain.txt                 ← 纯文本底稿（完整性核对用，保留溯源）
├── 01-正文.md                   ← AI 整理后的正文稿：去噪（页眉页脚/修订痕）、表格列表修复、图片引用就位
├── assets/images/               ← 图片目录（IMG_DIR 可配置；已拍平，图片直接可见、无 media/ 残留）
└── _clarify.md                  ← 待澄清清单（有疑点才生成）
```

## 需求加工档（可选，仅当用户要求「整理成需求规格 / 提炼需求点」时启用）

```
├── 01-需求规格.md                ← 需求点 + 验收标准（功能单元 ≤3 时单文件即可）
├── requirements/                ← 功能单元切片（单元 >3 时启用）
│   ├── REQ-01-{单元名}.md
│   └── ...
```

- 未要求需求加工：不出 01-需求规格.md 与 requirements/，01-正文.md 即最终正文稿
- 要求需求加工：01-正文.md 保留（溯源正文），另出 01-需求规格.md（≤3 单元单文件）或 requirements/ 切片（>3 单元时 01-需求规格.md 为总览：各单元一句话摘要 + 文件名映射）

## 整理规则

- 正文整理：保留原文关键表述与结构，修复表格/列表/图片引用，剔除页眉页脚/页码/修订痕噪音，不臆造内容
- 需求加工（可选档）：每条「需求点 - 验收标准」结对，保留原文关键表述；按业务功能边界切分，单元名用中文短名（如「用户登录」）；每个单元注明来源章节
- 澄清清单：校对中发现的歧义/缺失/矛盾 → _clarify.md 逐条编号记录（问题 + 原文出处 + AI 建议）
- 溯源：00-converted.md 保留不做删改，整理稿另写文件、不覆盖底稿

## 目录复用

- 输出目录已存在时：复用并覆盖本清单内同名文件（00-converted.md/01-正文.md 等），其余文件保留；不清空目录
