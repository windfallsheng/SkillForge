# 目录组织与落盘

## 默认输出结构

```
{源目录}/{文档名}-spec/          ← OUTPUT_DIR=auto 默认；可配置绝对路径
├── README.md                    ← 索引：源文档、转换时间、功能单元清单、校对记录摘要
├── 00-converted.md              ← Pandoc 机械底稿（AI 已校对修正版，保留溯源）
├── 00-plain.txt                 ← 纯文本底稿（完整性核对用，保留溯源）
├── 01-需求规格.md                ← AI 加工后的主规格：需求点 + 验收标准（功能单元 ≤3 时单文件即可）
├── requirements/                ← 功能单元切片（单元 >3 时启用）
│   ├── REQ-01-{单元名}.md
│   └── ...
├── assets/images/               ← 图片目录（IMG_DIR 可配置）
└── _clarify.md                  ← 待澄清清单（有疑点才生成）
```

## 加工规则

- 需求点提炼：每条「需求点 - 验收标准」结对，保留原文关键表述，不臆造内容
- 功能单元切分：按业务功能边界切分，单元名用中文短名（如「用户登录」）；单元 >3 时拆 requirements/ 目录，否则合并在 01-需求规格.md 内分章节
- 澄清清单：校对中发现的歧义/缺失/矛盾 → _clarify.md 逐条编号记录（问题 + 原文出处 + AI 建议）
- 溯源：每个功能单元注明来源章节；00-converted.md 保留不做删改，加工后的规格另写文件、不覆盖底稿

## 目录复用

- 输出目录已存在时：复用并覆盖本清单内同名文件（00-converted.md/01-需求规格.md 等），其余文件保留；不清空目录
