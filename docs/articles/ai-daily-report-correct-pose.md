# AI 写日报的正确姿势：从一句口述到三件套成品

> 关键词：AI 写日报 / 工作日报 / Agent Skills / 技能化工作流
> 仓库：[SkillForge](https://github.com/windfallsheng/SkillForge) · 技能简介：[SKILLS_CATALOG.md#daily-report](../../SKILLS_CATALOG.md)

把「帮我写今天的日报」直接丢给 AI，大概率得到三种翻车：一是流水账——把今天的事平铺一遍，没有主次；二是流水线味——满篇「赋能」「抓手」，不像你写的；三是失忆——明天再让它写，昨天的格式又变了。

问题不在 AI 不够聪明，而在每次对话都是零上下文起跑：它不知道你的工种、你的口径、你昨天怎么写的。正确姿势是把「怎么写日报」固化成技能——固定工序、行业词条、个人模板，一次配置，次次复用。

## 第一步：安装（一分钟）

```bash
npm i -g skill-forge-hub
skill-forge init        # 交互勾选 daily-report
```

## 第二步：口述，而不是写作

不用组织语言，一段大白话即可：

> 今天上午调通了支付回调的异常重试，下午排查了订单对账差异，明天准备联调退款流程。风险是第三方接口文档不全。

技能按固定三段结构产出：**任务进度 / 明日计划 / 风险阻塞点**。内置 12 个行业的职业词典，按你的角色取词——开发写「联调、回归」，产品写「验收、迭代」，话术不跑偏。

## 第三步：收三件套成品

一次生成三形态：对话里直接给 md 正文（贴群聊）；落盘 HTML 页面（发邮件、存文档）；导出 PNG 截图（一键贴图）。同一份内容，去哪都有合适的模样。

## 第四步：把调教沉淀成模板

觉得默认结构不够贴切？把常用写法写进 `user-config.md` 的自定义模板，之后每次生成自动套用；连日期都不必多说——「昨天的日报」「上周三的日报」自然语言直接定位。配置抽离在技能目录之外，升级技能不覆盖你的模板。

## 进阶：同一套口述，打通整条汇报链

同源的周报、月报、季报、年报共用这套口述习惯——本周结论先行、月度问题改进、季度环比同比、年度五段复盘。团队场景还有日报收集台：成员各自口述，汇总成按日期分组的团队报告。

## 结语

AI 写日报的正确姿势，不是憋出更长的提示词，而是把一次调教变成永久工艺。技能化之后，日报的稳定产出从「看运气」变成「按工序」——而这套工序，换哪个 AI 助手都走得通。
