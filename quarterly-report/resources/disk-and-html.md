# 落盘与 HTML（季度版式）

> ⛔ **Reference 铁律（最高优先）**：本目录 `reference.html` 是定稿样式源码。生成 HTML 时必须先 Read `resources/reference.html` 与本文件两份，以 reference.html 为骨架模板逐处替换数据（标题/日期/四段条目/TL;DR 摘要/数据卡数字与双基准小字/Q1-Q4 走势图数据数组——IIFE 内 QVALS），本文件的描述是参数解释、变体规则与禁止项；两者冲突时**以 reference.html 为准**。修改本 skill 的 HTML 效果时，必须同步更新 `resources/reference.html` 与本文档的对应描述，禁止只改一处。

> HTML 视觉体系与报表族（日报/周报/月报/年报）同源（深蓝面板 + 五主题令牌 + 发光特效 + 复制按钮 + 换肤坞 + 截图模式），生成时以 reference.html 为唯一样式真相源，本文件只列季报版式差异与要点。

## 落盘

- FORMATS 默认 [md, txt, html, content-png]：md/txt/html 文件名 `quarterly-report-YYYY-QN.<格式>`、截图 `quarterly-report-YYYY-QN-content.png`；txt 为纯文本版；DISK: false 时全部不落盘
- 目录：`{DIR}/YYYY-QN/`（DIR 按系统取 DIR_MAC/DIR_WIN，不存在回退用户主目录下 reports）；目录已存在直接复用，只覆盖本清单内同名文件；目录内存在非本 skill 命名的其它文件时对话中提示用户「该目录内已有其它文件，本次季度总结已与它们并列存放，未做任何改动」
- 对话中照常输出 md 正文（不受 FORMATS 影响）；OPEN_HTML: true 且落盘了 html 时自动打开浏览器（macOS：open <html文件>；Windows PowerShell：Start-Process <html文件>）
- 落盘完成后，对话回复必须向用户报告落盘位置：列出实际写入的目录完整路径与文件清单（如「已落盘到 ~/reports/2026-Q4/：quarterly-report-2026-Q4.md、.txt、.html、quarterly-report-2026-Q4-content.png」），并注明 html 是否已在浏览器打开、截图是否跳过（Chrome/Edge 都不存在时）；DISK=false 或未落盘时注明「本次仅对话输出，未落盘」
- FORMATS 含 content-png 时生成内容区截图：只截四张分节卡片整体（季度概览/季度关键成果/问题与改进/下季度计划，不含头部标题区/复制按钮/页脚，四周保留对称合适的外边距约 40px 留白）；html 内置 `?shot=content` 参数（页面 JS 检测后隐藏 header-card/footer、body 四周 padding 统一 40px，正常浏览不受影响）；用 Chrome headless 访问带参 URL 截图（路径按系统选：macOS=`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；Windows 按序探测 `C:\Program Files\Google\Chrome\Application\chrome.exe` → `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe` → `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`，经 node child_process 执行 `--headless --disable-gpu --no-sandbox --hide-scrollbars --user-data-dir=<临时目录> --screenshot=<png路径> --window-size=760,<估算高度> --virtual-time-budget=4000 "file:///<html路径>?shot=content"`（Windows 下 URL 写作 file:///C:/...，用 node url.pathToFileURL 生成），跑完删除临时目录；禁止用 `--headless=new`（单例模式会静默失败生成占位图）；若 Chrome 不存在则换 Edge，都找不到时跳过截图并在对话注明）；高度估算基准（760 宽窄窗实测：概览 4 卡折 2 行 + 走势图 200px、成果 6 条 + 2 占位月、问题 2 条三环、计划 3 条 → 内容区约 2350px，图高 = 内容区 + 上下留白各 40px）：每增减 1 条成果条目 ±~85、1 条问题 ±~100、1 条计划 ±~90、概览数据卡每多一行 ±~105；实测高度显著高于按 65~70px/条的旧估算，禁止低估导致截断，截图后用 Read 校验：四张卡片整体完整在图内、无头部/按钮/页脚残留、四周留白对称合适、不截断；底部留白过大减高度、截断加高度重截

## HTML 季度版式要点（基于 reference.html）

- 头部卡片：标题按行业词典「标题」变量取词 + 季度前缀（如「2026-Q4 研发季度总结」；话术含职业词 → 该词条标题，未提职业 → 按 ROLE 画像匹配词条，词典外行业 → 「YYYY-QN 季度总结」兜底）+ 副标题（ROLE 画像或季度区间）+ 生成时间行
- 概览节：一句话 TL;DR 引言行 + 核心数据卡 4-6 张横排（.stat-card：大数字 28px 渐变字 + 12px muted 标签 + **双基准两行小字**「较上季度：+18%」「较去年同期：+35%」，上涨 --green 绿、下跌 --rose 红，双基准均为 11.5px .stat-cmp 行，两行间距 2px；缺某一基准来源时只写有来源的一行，两条都没有则不写）；数据卡下方 Q1-Q4 季度走势图（.cb-wrap + .ech 容器 200px 高，echarts 柱图：xAxis Q1/Q2/Q3/Q4（当年已有季度，未到的季度不画）、当前季度柱高亮 accent 色、其余柱 muted 半透明，tooltip「QN · N 次提交」）
- 成果节：纵向时间线（.timeline 左侧 2px 青色竖线 + 月节点：M1/M2/M3 圆形节点（节色渐变球 + 光晕，当前月节点加呼吸动画）+ 右侧内容（成果描述 15px + 量化小字 12px 青灰 + 月徽章 11px muted 胶囊「M1 · 10 月」）；月内多条共用月节点，条目间青色虚线分隔；全季报（Q1-Q4 回顾）节点为 Q1/Q2/Q3/Q4
- 问题节/计划节：问题条目沿用 3D 立体圆球序号徽章（问题玫红）；问题条三环展开（问题主行 + 影响行 + 改进行）；计划条目卡（目标描述 15px + 量化指标加粗 + 月度行动节点小胶囊 11px（M1 起…/M2 完成…，muted 字 + 青色细边 + 淡青底））
- 数据卡数字选择：业务结果指标优先、提交统计兜底；数字凡有对比基准必带（环比上季度/同比去年同期至少其一）
- 页脚 10px muted 文字，署名固定 GENERATED BY AI TEAM · <季度>（动态跟随目标季度，如 GENERATED BY AI TEAM · 2026-Q4）
- 四段分节列表，条目保持中文顿号序号；md/txt 版同条目依次写，文本格式不变
