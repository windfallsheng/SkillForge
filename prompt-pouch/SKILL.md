# 锦囊 · 提示词管理台（prompt-pouch）

妙计入囊、随取随用：一个纯 HTML 的本地提示词管理台，页面与数据分离——双笔协作：页面可直写、AI 可代笔，用户只管说，刷新即见。

## 默认示例数据（INIT_DATA: example 时按此生成，可微调措辞）

面向所有职业的通用场景五组，每组 3 条，标题简洁（2-6 字），正文含 {变量} 插值：

## 执行流程

0. **读用户配置**（DIR/DIR_WIN/PORT/DATA_DIR/BACKUP_DIR/INIT_DATA/CONFIRM/THEME/CONFIG_VERSION）→ 先 Read 同目录 `user-config.md`
1. **初始化**（目标目录无 `prompt-pouch.html` 时）：
   - **目录确认**：用户未提目录 → 用配置 `DIR`；`CONFIRM: true` 时先 AskUserQuestion 确认（选项：用默认目录 / 换目录）；用户已说「放到 XX 目录」→ 直接用该目录（本次会话有效，不改配置文件）
   - 复制 `resources/reference.html` → `<DIR>/prompt-pouch.html`（原样复制，不修改任何样式与脚本；唯一例外：html 根标签 `data-theme` 属性值设为配置 `THEME`——reference 默认 "gold"，仅当配置非 gold 时替换该属性值）
   - 创建 `<DIR>/<DATA_DIR>/` 与 `<DIR>/<BACKUP_DIR>/` 子目录（配置为空串则跳过、平铺根目录）；生成 `<DIR>/<DATA_DIR>/prompts.json`：`INIT_DATA: example` 时写入「各职业通用」示例五组（写作输出/沟通协作/规划执行/复盘成长/提问艺术，每组 3 条，标题与正文按下方「## 默认示例数据」清单写，**每条必带 createdAt 当前时间（YYYY-MM-DD HH:mm:ss，写到时分秒）**）；`empty` 时写空结构（version + 空 groups/prompts）
   - 收尾提示启动方式：`cd <DIR> && python3 -m http.server <PORT>`（Windows 无 python3 时 `py -m http.server`），浏览器访问 `http://localhost:<PORT>/prompt-pouch.html`（HTTP 才能读 prompts.json；file:// 直开回退缓存快照）
2. **维护**（页面已存在时）：读 `<DIR>/<DATA_DIR>/prompts.json` → 按用户意图修改 → 写回（UTF-8、2 空格缩进、保留 version 字段）→ 提醒用户刷新页面
   - **分类交互**：用户说「添加 XX」但未说分组 → AskUserQuestion 列出全部现有分组（加「新建分组」选项）让用户选；用户指定的分组不存在 → 明确告知该分组不存在，并问是否新建（新建则补 groups 条目：id 16 位数字主键（雪花规则见 data-format.md）、name 中文、icon 一个 emoji）
2.5 **交付前自检**（初始化与每次维护落盘后必做，硬门禁不可跳过）：
   - **json 机器校验**：`python3 -c "import json;json.load(open('<DIR>/<DATA_DIR>/prompts.json',encoding='utf-8'))"`（Windows 用 py）解析通过，且 schema 自查无缺（version/groups/prompts 齐全、group 引用存在、order 连续、新增条目 createdAt 到时分秒）
   - **页面零报错验证**：Playwright headless（缺则 `pip3 install --user playwright`；用系统 Chrome，channel="chrome" 无需下载浏览器）→ 起本地服务 `cd <DIR> && python3 -m http.server <PORT>` → goto `http://localhost:<PORT>/prompt-pouch.html` → 挂 pageerror 监听（零容忍）→ 断言卡片数 `document.querySelectorAll('.card').length` 等于 prompts.json 的 prompts 条数（证明数据被正确读到；落回内置示例种子即自检失败）→ 收尾停服务
   - 未通过 → 修复后重跑，禁止跳过直接交付
3. **打开页面**：用户说「打开锦囊 / 打开提示词页面」→
   - 目标目录无页面时先执行步骤 1（初始化）
   - 后台起本地服务（`cd <DIR> && python3 -m http.server <PORT>`，Windows 用 `py -m http.server`；端口被占则换 PORT+1 再试）
   - 按平台打开浏览器：darwin → `open http://localhost:<PORT>/prompt-pouch.html`；win32 → `start` 同 URL；linux → `xdg-open` 同 URL
4. **结构规则与维护操作** → 读 `resources/data-format.md`（schema、id 规范、createdAt、updatedAt、排序落盘、插值语法、排序模式）
5. **批量整理入囊**（用户给一堆文字/文件/说「把最近对话框内容整理进锦囊」）：
   - 读 `<DIR>/<DATA_DIR>/prompts.json` 现状 → 逐条提炼候选提示词（标题/正文/建议归入哪个现有组/标签 1-3 个）
   - 输出整理方案表给用户：每条建议分组与理由；现有组装不下的条目推荐新建分组（中文名 + emoji icon + 一句推荐理由），不擅自落盘
   - 用户口述调整（换组/改名/删条目/改推荐组名）→ 确认后一次性落盘：id 雪花规则、createdAt 当天、各组 order 续排，写回前重读最新文件合并
   - 落盘后提醒用户刷新页面
6. **使用咨询**（用户只问「锦囊怎么用」等用法、未要求生成或修改）→ 读 `resources/usage-guide.md`，将其内容原样输出（首行标题改为「锦囊使用指南」），不读写任何文件

## ⚙️ 配置与自定义主题

**执行本 skill 前必须先 Read 同目录 `user-config.md`**：目录（DIR/DIR_WIN）、端口（PORT）、初始化数据（INIT_DATA）、确认开关（CONFIRM）、主题（THEME）等默认配置都在该文件中，以它为准。升级技能时 user-config.md 不会被覆盖，你的修改永久保留。

**THEME 主题机制**：页面内置四套主题——gold 暖棕金（默认）/ tech 深蓝科技 / mono 极简黑白 / mint 薄荷绿。初始化复制 reference.html 后，将 html 根标签 `data-theme` 属性值设为配置 `THEME`（仅此一处修改）；页面右下角「换肤坞」色点可随时切换主题，选择经浏览器 localStorage 持久（key: sf-pouch-theme），刷新后保持；localStorage 优先级高于根标签 data-theme。已初始化的页面改配置 THEME 不追溯——用户手动换过主题即以其选择为准。

**配置版本机制（升级保护）**：user-config.md 头部 `CONFIG_VERSION` 标识结构版本。升级 skill 后若发现新版本结构（如 v2 新增 THEME 字段）而用户配置是旧版：先备份旧配置为 `user-config.md.bak-时间戳`，将旧值迁移进新结构（保留用户已有 DIR/PORT/INIT_DATA/CONFIRM，缺失字段补默认值），更新 CONFIG_VERSION，最后用一句话告知用户配置已升级、旧文件备份在哪。 **无法迁移项处理**（值域失效 / 语义漂移 / 数据不兼容）：三绝不——绝不静默（无法迁移项停下问，不猜值）、绝不丢失（旧值永远在备份）、一次说清（升级报告三段式：⚠️ 版本与备份路径 / ✅ 已自动迁移 / 🟡 无法迁移项逐条附原因+影响+建议替代）；随后 AskUserQuestion 三选项（A 用建议值 / B 用户给新值 / C 保持旧配置——不更新 CONFIG_VERSION，每次执行再提醒）；报告必附回滚一句话；数据文件（prompts.json）迁移前先复制 .bak-时间戳，能映射则映射、不能则写兼容层（旧 id 兼容保留即范例）或留备份提示手动整理

## 核心约束

- **页面与数据分离**：HTML 不内嵌用户数据——一切用户数据只进 <DATA_DIR>/prompts.json；HTML 内置只读示例种子（DEFAULT_POUCH 五组 15 条），仅当 prompts.json 读不到且浏览器无缓存快照时兜底展示（file:// 直开也能看到示范数据），一旦读到 prompts.json 即以文件为准；样式升级只改仓库 reference.html 后重新复制到目标目录（用户数据不受影响）
- **目录结构（v3）**：数据文件默认 `<DIR>/<DATA_DIR>/prompts.json`（默认 cache/），自动备份默认 `<DIR>/<BACKUP_DIR>/`（默认 backup/，pouch-backup.json + .prev.json 滚动双备份）；页面读侧兼容旧平铺结构（新路径读不到时兜底读根目录旧文件），写侧一律写新路径；AI 初始化/维护时发现旧平铺结构（根目录 prompts.json / pouch-backup*.json）→ 建子目录并迁移文件（迁移前先复制 .bak-时间戳），一句话告知用户
- **双笔协作**：页面（授权目录时）与 AI 都可写 prompts.json——页面上有「＋ 新增提示词 / ✎ / 🗑 / 分组管理」表单直写；AI 落盘前必须重读最新文件再合并写回（见「页面双笔纪律」）
- **prompts.json 结构必须合法**：写回前自查 schema（version/groups[]/prompts[] 各字段齐全、group 引用存在、order 连续）
- **排序四模式**：页面顶栏切换「最新添加（默认，按 createdAt 倒序）/ 最近使用 / 使用频率 / 手动顺序」；最近使用与使用频率由页面在复制时自动统计（浏览器本地态，AI 不落盘）；用户在非手动模式下拖动卡片或点 ▲▼ 会自动切回手动顺序、点卡片 ⇄ 可把提示词移到其它分组——用户随后粘贴「复制变更指令」，AI 必须按指令落盘：先执行「分组调整」节（改各条 group），再按「各组顺序」节每组列出的顺序重写各条 `order`，写回后提醒用户刷新并点页面「✓ 已落盘」清除标记
- **id 规范**：组与提示词的 id 均为 16 位纯数字主键（雪花变体 = 13 位毫秒时间戳 + 3 位随机数，如 1762500000123456），全库唯一、删除后不复用、跨导出导入不冲突；AI 生成时按当前日期时间换算 13 位毫秒戳 + 自选 3 位随机数，与现有 id 重复则只换随机段；旧版「slug+序号」字符串 id（如 w05）兼容保留不迁移，新数据一律数字雪花 id（详见 data-format.md「id 生成规则」）
- **createdAt 规范**：新增提示词必写 `createdAt`（当天日期，YYYY-MM-DD 或完整 ISO 8601），它是「最新添加」默认排序的依据；旧数据可无此字段
- **updatedAt 规范**：AI 修改提示词（改标题/分组/内容/标签）时同步写/更新 `updatedAt`（当天日期，格式同 createdAt）；仅重排 order 或改收藏不更新；新增不写（视为无修改）
- **页面双笔纪律**：页面经目录授权后可直写 prompts.json（增删改分组与提示词、排序落盘）。AI 每次维护必须先重读最新 prompts.json 再修改写回，严禁基于会话早期读入的旧内容覆盖写回（会丢失页面刚写入的改动）；页面未授权目录时的操作会生成「复制指令」交回 AI，按指令内容落盘
- **插值语法**：内容里的 `{变量名}`（如「{功能名}」）会被页面自动识别为填充面板变量，写内容时按需保留花括号占位
- **主题令牌纪律**：reference.html 组件样式一律引用 CSS 变量（--gold/--gold2/--gold-dim/--border/--tag-bg/--star/--glow/--bar-hi/--bar-lo 等），禁止在组件侧硬编码暖棕金色值（#e8b04b、rgba(232,176,75,…)、rgba(23,17,12,…)）；新增样式需复用现有令牌或先在四主题块中各补一致定义；改主题只改对应 [data-theme] 块，不动组件
