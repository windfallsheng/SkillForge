# 月度总结使用指南

## 能干什么

把一个月的工作沉淀成四段式月度总结：月度概览（一句话 TL;DR + 核心数据卡，数字带环比上月基准）/ 本月关键成果（W1-W4 周时间线）/ 问题与改进 / 下月计划。适配各行业：内置 12 行业职业词典，报职业自动换术语、指标与标题（如「2026-11 研发月度总结」「2026-11 销售月度总结」）；不报职业按你的默认角色画像生成。

## 基本用法
- 直接说「写月报 / 生成月度总结」→ 默认生成当前自然月的总结，无需指定月份
- 指定月份（多种说法均可）：
  - 「2026 年 11 月的总结 / 这个月的总结」→ 当前自然月（未过完只算到「今天」，标题注明「截至 2026-11-12」）
  - 「上个月的总结 / 10 月的总结」→ 上一自然月
  - 「近一个月的总结 / 最近 30 天的总结」→ 滚动 30 天（今天往前推 30 天）
  - 「2026-10 的总结」→ 明确指定的自然月
- 同一份月度总结重复生成默认直接覆盖；说「保留之前的 / 另存 / 不覆盖」→ 文件名追加时间戳另存不覆盖
- 说「打开 / 查看 2026 年 11 月月报」→ 该报告文件已存在时直接打开不重新生成；不存在则按正常流程生成
- 开发类用户可说「只算我的提交」→ 只聚合本人提交；默认仓库内全部提交都计入
- 说「只聚合 xxx 仓库 / 只写 xxx 的月报」→ 只收集指定仓库的提交，跳过其它仓库

## 口头补充素材
- 说「补充一下：这个月上了对账系统，月底拿下了金融客户」→ 自动按语义拆成多条，润色为规范格式并入对应周与段落
- 拆分信号：时间词（月初/第一周/月中/月底/W1/W2）、连接词（还有/另外/以及）、分号顿号列举、数字列举
- 补充内容带分段词时按段并入：「下月计划：做 XX」→ 下月计划段；「问题：复盘机制缺失」→ 问题与改进段；不带分段词按语义归段（成果 → 成果段，感悟 → 概览或问题段）
- 与提交记录聚合出的成果自动去重，同一件事只保留一条（量化以提交统计为准、定性以口述为准）

## 贴文字 / 发图片 / 给文件整理（没有提交记录也适用）
- 直接贴一段文字说「整理成月报 / 把这段文字整理成月报」→ 以文字为主源生成，不依赖提交记录（非开发岗位也可用）；说「只整理这段文字 / 只按这段」同样跳过其它来源与会话上下文
- 发图片（截图/照片等 jpg/png/webp）或给文件（md/txt/docx/pdf 等）说「整理成月报」→ 先用 Read 读取：图片按视觉理解提取图中文字信息，md/txt 直接读文本，docx/pdf 优先尝试 pandoc 转文本（无 pandoc 则请用户粘贴文字），再按纯文字模式整理；聊天记录/周报/日报/会议纪要文件也可作为素材
- 图片模糊/内容读不清时：先把已提取的部分展示给用户确认或补充，不瞎编没读到的内容
- 素材不足的段写「暂无」并提示用户可补充素材
- 默认直接生成落盘（CONFIRM: never，无需确认）；把顶部 CONFIRM 改为 text/always，或临时说「先看看效果/先出效果」→ 先在对话输出整理好的报告正文，用户说「可以/确认/落盘」→ 再落盘文件与内容区截图并开 html；说「改一下 xxx」→ 按意见修改后重新出效果再确认
- 说「不用确认/直接落盘」→ 当次跳过确认直接落盘（临时要求优先于配置）
- 说「不落盘/别写文件」时跳过确认，直接对话输出

## 自定义模板（适配各类岗位）
- 内置模板为四段式（月度概览/本月关键成果/问题与改进/下月计划），适合开发岗位；其他岗位可自定义模板
- 临时换模板：说「这次按 xxx 来」→ 口头描述结构（如"按三段：本月工作概述/重点成果与经验/下月计划"），当次按该结构生成，不改配置
- 永久换模板：把顶部配置 TEMPLATE 改为 custom，并按 user-config.md 的「📝 自定义模板」节说明修改段结构，之后默认按新模板生成
- 说「以后都用这个模板」→ 自动把当前口述的结构写入「📝 自定义模板」节并把 TEMPLATE 改为 custom
- 升级保护：「📝 自定义模板」节改的内容升级永不覆盖——skill-forge 升级技能只更新 SKILL.md 与 resources/，user-config.md 永远保留你的版本；官方内置模板更新另存 user-config.upstream.md 对照，不影响你的模板
- 模板优先于纯文字模式的信号词归类：指定了段名后，文字按段名归类填充

## 角色定制（我的职业画像）
- 默认按顶部「默认配置」ROLE 生成（当前：全栈开发工程师（企业内技术开发））；说「我的职业是 XX / 我的主要工作是 XX / 以后默认用 XX 角色」→ 永久修改 ROLE
- 说「以 XX 的身份写月报」→ 当次按该角色生成（内置 12 行业词条：研发/销售/运营/产品/HR/财务/市场/客服/项目/行政/法务/设计可直接用），不改配置
- 标题随职业词条变化：研发 →「2026-11 研发月度总结」、销售 →「2026-11 销售月度总结」等
- 词典外行业走兜底：按骨架 + 你提供的素材现场生成词条；说「记住这个行业」→ 固化为新词条

## 控制落盘（临时要求，仅对当次生效）
- 默认：对话输出 Markdown + md/txt/html 三文件 + 内容区截图 content-png 落盘到 DIR（auto 按系统选：macOS=~/reports、Windows=%USERPROFILE%\reports，模板默认值，路径以 user-config.md 顶部「默认配置」为准）/YYYY-MM/ + html 自动打开（DIR 目录/盘符不存在时自动改用用户主目录下 reports：macOS=~/reports、Windows=%USERPROFILE%\reports）
- 说「写到桌面」→ 本次落盘到桌面（macOS=~/Desktop、Windows=%USERPROFILE%\Desktop）；说「存到 ~/report / D:\report」→ 本次用指定目录（均自动按月份建子目录）
- 说「不落盘/别写文件」→ 本次只在对话输出，不写文件、不开浏览器
- 说「只要 md」「只出 html」「只要内容区截图」→ 本次只落指定格式文件；说「这次不截图」→ 本次跳过截图（content-png = 四张分节卡片整体一张图，四周约 40px 留白，不含头部标题、复制按钮、页脚）
- 说「只要截图/重新截个图」（如「给 2026-11 月报截个图」）→ 本次不重新生成内容，只对现有 html 执行内容区截图（覆盖 content-png，需 html 已存在，找不到则提示先生成）
- 说「别开浏览器」→ 本次落盘后不自动打开 html
- 说「保留之前的」→ 同月份重复生成时不覆盖，文件名追加时间戳另存

## 配置开关（改 user-config.md 顶部「默认配置」节，长期生效）
| 配置项 | 作用 | 可选值 / 示例 |
|---|---|---|
| DISK | 是否落盘写文件 | true（落盘，默认）/ false（默认只在对话输出） |
| FORMATS | 落盘哪些格式（数组） | [md, txt, html, content-png]（默认，含内容区截图）/ [md, html] / [md, txt, html]（不截图）；content-png = 四张分节卡片整体截图（四周约 40px 留白），不含头部标题/复制按钮/页脚 |
| DIR | 落盘根目录 | auto（按当前系统自动选 DIR_MAC / DIR_WIN，默认）；DIR_MAC = macOS 根目录（模板默认 ~/reports，可改）；DIR_WIN = Windows 根目录（模板默认 %USERPROFILE%\reports，可改） |
| OPEN_HTML | 落盘后是否自动打开 html | true（自动打开，默认）/ false（不打开） |
| TEMPLATE | 报告模板 | default（内置四段式，默认）/ custom（按「📝 自定义模板」节的结构生成） |
| ROLE | 默认职业角色画像 | 全栈开发工程师（企业内技术开发）等；职业名 + 括号内工作内容 |
| CONFIRM | 落盘前先出效果确认 | never（直接生成不确认，默认）/ text（纯文字整理模式确认）/ always（所有生成都确认） |
- 优先级：临时口头要求（不落盘/写到桌面/只要 md/只要内容区截图/这次不截图/别开浏览器/临时换模板等）永远优先于默认配置，仅对当次生效、不改配置
- DIR（按系统解析）指向的目录/盘符不存在时，自动回退到用户主目录下 reports（macOS=~/reports、Windows=%USERPROFILE%\reports）

## 效果不对怎么办

- 页面效果不对（布局乱 / 样式错 / 交互异常 / 内容显示不全），直接对 AI 说「这个页面效果不对，对照参考模板修复」，把问题描述清楚（哪一节、什么现象，能截图最好）
- 本技能的设计标准答案就在技能目录里：`resources/reference.html`（双击可直接打开看标准效果），AI 修复时以此为唯一对照
- AI 的处理流程固定：先打开 reference.html 作标准 → 再读你那份问题 html 文件 → 逐处比对找出跑偏的地方 → 以 reference 为准修复 → 用浏览器自动截图对比修复前后，自证修好了再交付
- 效果对了但内容不对（数字/条目写错）同样说「内容有误：xxx 应该是 xxx」，AI 只改数据不动版式；参考模板本身有缺陷时（生成结果与 reference 一模一样但仍有问题）说一句「参考模板也有这个问题」，AI 会连模板一起修并同步回 reference.html
- 修复后想要永久按修复效果生成：说「以后都按这个效果生成」即可
