## ⚙️ 配置与自定义

## 配置版本机制（升级保护）

本 skill 当前配置版本为 `1`（对应 user-config.md 中的 `CONFIG_VERSION`）。执行时若发现 user-config.md 的 CONFIG_VERSION 与本节声明的当前版本不一致：

1. 先将旧 user-config.md 备份为 `user-config.bak-<时间戳>.md`（同目录，绝不删除旧值）
2. 按本节「配置升级规则」迁移字段：新增字段补默认值、改名字段按映射改写、删除字段的值保留在备份中并在对话提示用户手动确认
3. 更新 CONFIG_VERSION 为当前版本
4. 对话中明确告知用户「检测到配置版本从 X 升级到 Y，旧配置已备份至 <路径>」

升级本 skill 时，配置结构如有变化必须同步更新本节的当前版本号与迁移说明；禁止在未声明版本变更的情况下静默修改配置语义。

## 产物升级（回炉）——仅含 HTML 输出的技能保留本节，否则删除

生成 HTML 时头部写版本戳 `<meta name="sf-template" content="<skill>@1">`（模板升级时递增 @N 并同步 reference.html 与本文档）。用户说「升级旧产物/回炉旧页面/旧XX换新样式」时：扫落盘目录读版本戳筛出旧版（无版本戳或缺少稳定 ID meta 的产物视为 v0 最旧版，一并进清单）→ 列清单（文件/旧版本/手改状态）→ AskUserQuestion 选全部或部分 → 逐份升级：浅升级（仅 CSS/JS 变化）对旧页替换 `<style>` 块与交互脚本、正文原样保留；深升级（DOM 结构变化）从同目录 md 底稿按当前 reference.html 重建且**沿用原页稳定 ID meta 值**（用户数据类换 ID = 数据失联），先备份旧版 `.bak-时间戳` → 报告三段式：✅ 已升级清单 / ⚠️ 手改保留说明 / 🟡 失败项原因。模板改动分级：业务改动（板块/段落/标题体系）、数据格式改动（字段/存储结构）、页面改动（样式/布局/交互）任一发生即模板升级，版本戳 +1 并同步 reference.html 与本文档；纯措辞润色不 bump。每次生成 HTML 时顺扫落盘目录读版本戳：发现旧版产物主动告知「技能模板已升级至 vN，检测到 X 份旧版产物，说『把我旧XX都升级成新样式』即可一键升级」，不让用户背触发语。（工具型产物——固定页面反复打开、数据累积——每次调用本 skill 全时机顺扫，执行流程第 0 步后固定加「版本自检（静默前置，全时机）」步骤：静默比对版本戳、结果只影响提示不影响执行；打开场景主动问——起服务前 AskUserQuestion「A 升级后打开（推荐）/B 直接打开旧版（本次会话不再问）」附更新点清单；维护/取用场景收尾一句话轻提示；拒绝过后本会话静默）
