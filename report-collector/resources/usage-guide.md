# 通用数据采集器使用指南

> 本指南回答「report-collector 怎么用」的全部问题。当用户询问本技能用法时，将本文件内容原样输出（首行标题改为「通用数据采集器使用指南」）。

## 一、这个技能是干什么的

一句话：**给日报/周报/月报/季报/年报五个统计技能配一个统一的数据入口。**

写报告时，AI 需要知道你最近干了什么——最可靠的证据就是代码仓库的 git 提交记录、本地的工作文件、远程的数据接口。以前这五份技能各写各的采集命令，口径不统一；现在统一由本采集器一次取齐：跑一个脚本、出一份标准 JSON、带一句采集摘要反馈。你在本技能配置一次数据源，五个统计技能全部自动受益。

**三大能力**：

| 能力 | 说明 |
|:---|:---|
| 三通道采集 | git 仓库（提交数/增删行数/日周月分布/版本里程碑）、本地文件目录（文本要点）、远程 URL（拉取内容），按你配置的清单一次取齐 |
| 标准 JSON | 统一数据结构输出，五种周期（日/周/月/季/年）只是时间窗口参数不同，采集逻辑零差异 |
| 增量缓存 | 同一窗口重复采集免重扫（改模板重跑报告、同一天反复生成，git 扫描只跑第一次） |

**与五个统计技能的关系**（业内「三 Skill 流水线」模式的第一环）：

```
report-collector（数据聚合） → 五统计技能（趋势分析 + 报告生成）
```

你配置在**本技能** user-config.md 的 DATA_SOURCES 就是唯一真相源——五个统计技能收集数据时读它、跑采集器取 JSON。它们各自 user-config.md 里的 DATA_SOURCES 字段保留为「单技能补充源」（只在本技能生成时追加采集），一般不填，避免两处维护。

## 二、首次使用三步走

### 第 1 步：安装本技能

用 skill-forge 安装（与其他技能一致）：

```bash
skill-forge init --skills report-collector
```

验证 Python 环境（脚本运行前提）：macOS 自带 `python3`；Windows 需到 python.org 安装并在终端确认 `python --version` 可用。**没有 Python 也能用**——AI 会按手工命令模板降级采集，只是失去增量缓存等脚本能力。

### 第 2 步：配置数据源（一次配置，永久复用）

对本技能说：

> 把 /Users/我/Projects/主项目 这个仓库加进数据源
> 再把 ~/Documents/周例会纪要 目录也加进去
> 再加个远程数据接口 https://example.com/data.json

AI 会写入 `user-config.md` 的 `DATA_SOURCES` 清单（升级保护区，skill 升级永不覆盖）。也可以直接手改该文件。**不需要在五份统计技能里重复配置**。

### 第 3 步：正常使用五统计技能

配置完成后，说「写个日报」即可——统计技能会自动跑采集器取数，并在生成前先回一句采集摘要（如「已从 3 个仓库聚合 47 次提交、2 个文件提取要点」），让你确认数据来源后再成稿。**用户侧感知 = 多了一句数据来源反馈，其余无感。**

## 三、数据源配置详解

`DATA_SOURCES` 是一个数组，每项一个数据源，三种类型：

### 通用字段

| 字段 | 必填 | 说明 |
|:---|:---|:---|
| name | 是 | 唯一名称（重名视为同一数据源；以后口述「只聚合 xxx」按它匹配） |
| type | 是 | `git` / `file` / `remote` 三选一（拼写错误 = 忽略该项并在摘要中提示） |

### type: git（代码仓库）

| 字段 | 说明 |
|:---|:---|
| mac | macOS 路径（绝对路径或 `~` 开头）；「-」= 该系统不存在 |
| win | Windows 路径（如 `D:\Projects\main-app`）；「-」= 该系统不存在 |

采集产出：窗口内逐条提交（hash/说明/涉及文件/增删行数）、总提交数、增删行数、按日/周/月分布、里程碑（tag 版本发布 + merge 合并）、高频文件 Top8。路径不存在或非 git 仓库时静默跳过（摘要中说明原因）。

### type: file（本地文件/目录）

| 字段 | 说明 |
|:---|:---|
| mac / win | 同上；指向文件 = 提取该文件要点；指向目录 = 递归扫文本文件（md/txt/csv/log/json/yaml，二进制与超大文件自动跳过，单源最多 200 个） |

### type: remote（远程网络源）

| 字段 | 说明 |
|:---|:---|
| url | 网页或数据接口地址（有 mac/win 字段时忽略，只看 url）；拉取失败/超时静默跳过不阻塞 |

### EXCLUDE_EXTRA（可选，追加生成物剔除）

脚本内置剔除表（node_modules、dist、build、vendor、.venv、__pycache__、.git、.next、.nuxt、.cache、coverage、.speccore、.build、*.lock、*.min.js、*.min.css、*.map、.DS_Store），这些路径的行数不计入统计（防 graph.json 之类生成物灌几十万行噪音）。仓库另有独特生成物时追加：

```yaml
EXCLUDE_EXTRA:
  - (^|/)generated/
```

剔除是透明的：采集摘要会展示「剔除生成物 +X/-Y」，JSON 里也有 excluded 明细，口径可自证。

## 四、五种周期怎么用（窗口参数对照）

五个统计技能自动传参，你无需关心；了解即可：

| 技能 | --since / --until | 附加参数 | 说明 |
|:---|:---|:---|:---|
| 日报 | 目标日当天 | — | 一天窗口，秒级完成 |
| 周报 | 周一 ~ 周结束日（默认周五） | — | 周分布数组直接喂热力图 |
| 月报 | 月首 ~ 月末 | — | 月分布喂日历热力图 |
| 季报 | 季首 ~ 季末 | — | 环比/同比需另跑上季/去年同季窗口 |
| 年报 | 1月1日 ~ 12月31日 | `--full` | 全量重扫忽略缓存，保证年度数据完整 |

## 五、增量缓存（report-state.json）

- **位置**：`~/.skillforge/report-state.json`（Windows：`%USERPROFILE%\.skillforge\report-state.json`）
- **语义**：同一仓库、同一时间窗口、上次采集成功 → 下次直接复用上次结果（免重扫）；窗口变了 → 全量重扫
- **收益场景**：同一天反复生成日报（改模板、改措辞重跑），git 扫描只跑第一次；写日报后马上写周报，窗口不同自动全量扫
- **安全**：缓存文件可随时删除（下次重扫重建）；file/remote 通道不缓存（内容需要新鲜）

## 六、采集摘要反馈与失败兜底

每次采集后，AI 会先回一句数据来源摘要再开始写报告，例如：

> 已从 3 个数据源聚合：主项目仓库 47 次提交（+1234/-567 行，剔除生成物 +38000/-32000）、周例会纪要 3 个文本文件；1 个远程源拉取失败已跳过。

- **全部失败**（数据源全部不可用）→ AI 明确告知并退回纯口述模式——你直接口述内容照常成稿，不阻塞
- **部分跳过** → 摘要中点名跳过项与原因（路径不存在/拉取失败），修好配置后重跑即恢复

## 七、常见问题

**Q：我已经在日报的 user-config.md 里配过数据源了，要搬家吗？**
A：不用搬。已填的配置作为「单技能补充源」继续生效；新数据源建议统一配到本技能（一份清单五报通用）。两处重名的数据源以本技能清单为准。

**Q：为什么统计的行数和我手动 git log 看到的不一样？**
A：口径差异 = 生成物剔除。node_modules、.speccore/code-graph/graph.json 等生成物不计入统计（否则一个 graph.json 就能灌几十万行）。采集摘要里的「剔除生成物 +X/-Y」就是差值来源。

**Q：采集很慢吗？**
A：日报一天窗口通常秒级；年报全年窗口视仓库大小数秒到数十秒，命中缓存时第二次起免重扫。

**Q：数据源路径错了/仓库搬家了怎么办？**
A：该数据源静默跳过并在摘要中提示「路径不存在」，报告不受影响；说「数据源 xx 的路径改成 <新路径>」让 AI 更新清单即可。

**Q：会联网泄露我的数据吗？**
A：只有你配置了 type: remote 的 URL 会被脚本访问（且只在你生成报告时）；git/file 通道纯本地；token 类配置后续扩展时也只在本地 user-config.md 保存。

## 八、扩展规划

- **已评估待落地**：Jira/TAPD/禅道 API 子命令（token 放 user-config.md 用户自填，不落记忆）、本地 iCal 日历文件
- **不纳入**：飞书/钉钉接口（需企业权限，个人场景价值低）、常驻后台监听（AI 技能不是服务进程；git log 天然累积，按需查询即可拿到全部历史——这正是本采集器的设计前提）
