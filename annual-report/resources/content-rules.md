# 内容规则（五段式）

五段式骨架行业无关（任何职业通用），术语与指标由职业词典适配。

## 段结构

**段一 年度概览**
- 一句话 TL;DR：全年工作的总体判断（如「交付密集的一年：全年完成 3 个版本迭代，代码库净增 4.2 万行」）
- 核心数据卡 3-6 项：年度最关键的量化指标（按职业词典），每项：数字 + 单位 + 标签
- 可带同比小字（「较去年：+18%」）

**段二 核心成果与里程碑**
- 按季度（Q1/Q2/Q3/Q4）时间线排列 8-12 项，每项：成果描述 20-40 字 + 所属季度 + 量化结果
- 里程碑事件优先（版本发布/项目上线/重大交付），日常任务不逐条列
- 未过完的季度（如写到 Q4 中途）注明「截至当前」

**段三 经验与成长**
- 3-5 条，每条一句话：沉淀的方法/技能/认知（「沉淀了 XX 方法」「掌握了 XX」）
- 强调可复用（对未来有用的才写），不写「完成了 XX」这类成果句（归段二）

**段四 不足与反思**
- 2-4 条三环结构：问题（是什么）+ 影响（导致什么）+ 改进（明年怎么改）
- 具体诚实，不写「还需努力」这类空话；无真实不足才写「暂无」

**段五 新年展望与规划**
- 年度目标 3-5 项：目标描述 + 可量化指标（「完成 XX，年底达到 XX」）
- 每项目标带分季度行动节点（Q1 起…Q2 完成…）
- 目标与段四不足的改进方向呼应

## 写作风格

- 中文顿号序号（1、2、3），段内条目数按上述区间；不足处写「暂无」
- 量化优先：能带数字的带数字，估算值注明「约」
- 语言朴素具体，杜绝「再接再厉/砥砺前行」等套话；全年视角有判断、有取舍，不是流水账
- md/txt 正文含生成时间行（精确到时分秒，如 2026-11-06 19:10:38）

## 聚合来源与纯文字模式

- git 聚合来源（提交统计/里程碑）与口述来源（大事/感悟）合并后按段归类；两者矛盾时量化以 git 为准
- 纯文字/图片/文件整理模式（无 git）：用户提供什么用什么，按五段结构归类；素材不足的段写「暂无」并提示用户可补充素材
