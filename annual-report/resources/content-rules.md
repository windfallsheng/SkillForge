# 内容规则（五段式）

五段式骨架行业无关（任何职业通用），术语与指标由职业词典适配。

## 段结构

**段一 年度概览**
- 一句话 TL;DR：全年工作的总体判断（如「交付密集的一年：全年完成 3 个版本迭代，代码库净增 4.2 万行」）
- 核心数据卡 3-6 项：年度最关键的量化指标（按职业词典），每项：数字 + 单位 + 标签；数字凡有对比基准必带（同比/目标完成度至少其一），无基准来源不作要求
- 可带同比小字（「较去年：+18%」）

**段二 核心成果与里程碑**
- 按季度（Q1/Q2/Q3/Q4）时间线排列 8-12 项，每项：成果描述 20-40 字 + 所属季度 + 量化结果 + 价值归因（做了什么→改变了什么→与年度目标的关联，如「重构下单链路，响应 3.2s→0.4s，支撑双11峰值」）
- 里程碑事件优先（版本发布/项目上线/重大交付），日常任务不逐条列
- 未过完的季度（如写到 Q4 中途）注明「截至当前」

**段三 经验与成长**
- 3-5 条，每条一句话：沉淀的方法/技能/认知（「沉淀了 XX 方法」「掌握了 XX」）；个人成长与判断允许第一人称「我」（「我沉淀了 XX」「我意识到 XX」），团队经验用「我们」
- 强调可复用（对未来有用的才写），不写「完成了 XX」这类成果句（归段二）

**段四 不足与反思**
- 2-4 条三环结构：问题（是什么）+ 影响（导致什么）+ 改进（明年怎么改，含可验证动作与时间节点，如「Q1 引入 code review 制度，季度缺陷率降到 X%」）
- 具体诚实，不写「还需努力」这类空话；无真实不足才写「暂无」

**段五 新年展望与规划**
- 年度目标 3-5 项：目标描述 + 可量化指标（「完成 XX，年底达到 XX」）+ 完成标准（可验证的终点；杜绝「努力提升 XX」类不可验证表述）
- 每项目标带分季度行动节点（Q1 起…Q2 完成…）
- 目标与段四不足的改进方向呼应

## 写作风格

- 中文顿号序号（1、2、3），段内条目数按上述区间；不足处写「暂无」
- 量化优先：能带数字的带数字，估算值注明「约」；用户口述的业务结果指标（响应时间/错误率/成功率等）优先于 提交统计（提交数/行数/版本数），提交统计作兜底
- 语言朴素具体，杜绝「再接再厉/砥砺前行」等套话；全年视角有判断、有取舍，不是流水账；流水与清单条目保持无主语，结论/判断/归因处允许第一人称「我」
- 技术动作翻译：口述技术动作且带结果数据时，翻译为业务结果表述（「重写 SQL 加索引」→「查询响应 3.2s→0.4s」）；仅含动作无结果时保留动作，并提示可补充结果指标
- 落笔前五问自检：①第一句是不是结论？②数字有没有对比基准？③卡点有没有责任动作和时间？④计划能不能被验证？⑤个人贡献与团队成果的归属是否清晰？任一不过，改写后再输出
- md/txt 正文含生成时间行（精确到时分秒，如 2026-11-06 19:10:38）

## 聚合来源与纯文字模式

- 提交记录聚合来源（提交统计/里程碑）与口述来源（大事/感悟）合并后按段归类；两者矛盾时业务结果指标以用户口述为准、提交统计（提交数/行数）兜底
- 纯文字/图片/文件整理模式（没有提交记录）：用户提供什么用什么，按五段结构归类；素材不足的段写「暂无」并提示用户可补充素材
