# 收集数据（阶段 1）

## 数据来源（三种，可混用）

1. **口述**：用户直接说「张三：今日做了 A，明日做 B，无风险」「李四的日报：…」→ 逐人整理为字段
2. **文件批量**：用户给 md/txt/csv/xlsx 文件（每位成员一段/一行）→ Read/解析后按人拆条；csv/xlsx 表头需含 成员/日期/进展/计划/风险 任几列，缺失列留空
3. **页面导出导入**：用户在收集台页面填完点「导出 JSON」得到 reports.json → 用户发回该文件时以它为准合并（同成员同日期覆盖旧值）

## 字段规范

| 字段 | 说明 |
|:---|:---|
| name | 成员名（显示用） |
| date | 日报日期 YYYY-MM-DD（缺省用 REPORT_DATE 或今天） |
| progress | 今日进展（做了什么） |
| plan | 明日计划（准备做什么） |
| risk | 风险阻塞（无则空字符串，不写「无」之外的套话） |

## 合并去重

- 同一成员（name）+ 同一天（date）多条 → 合并：progress 以「；」拼接、plan 同样拼接、risk 合并去重
- 日期统一 YYYY-MM-DD；成员名保留用户原话写法（不擅自改花名/英文名）
- 收集结果清单（成员数 / 日报条数 / 缺报成员提示——TEAM 只影响标题不影响名单，名单以本次收集实际成员为准）展示给用户确认后进阶段 2
