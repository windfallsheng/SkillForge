# 落盘与 HTML（会议纪要版式）

> ⛔ **Reference 铁律（最高优先）**：本目录 `reference.html` 是定稿样式源码。生成 HTML 时必须先 Read `resources/reference.html` 与本文件两份，以 reference.html 为骨架模板逐处替换数据（标题/日期/五段条目/TL;DR 摘要/决策列表/议题卡/行动项表格行/下次会议卡），本文件的描述是参数解释、变体规则与禁止项；两者冲突时**以 reference.html 为准**。修改本 skill 的 HTML 效果时，必须同步更新 `resources/reference.html` 与本文档的对应描述，禁止只改一处。

> HTML 视觉体系与日报/周报/月报/季报/年报同源（深蓝面板 + 五主题令牌 + 发光特效 + 复制按钮 + 换肤坞 + 截图模式），生成时以 reference.html 为唯一样式真相源，本文件只列会议纪要版式差异与要点。

## 落盘

- FORMATS 默认 [md, txt, html, content-png]：md/txt/html 文件名 `meeting-minutes-YYYY-MM-DD-{主题slug}.<格式>`（主题 slug 用简洁英文或拼音，如 spec-release；无主题时省略 slug 段：`meeting-minutes-YYYY-MM-DD.html`）、截图 `meeting-minutes-YYYY-MM-DD-{主题slug}-content.png`；txt 为纯文本版；DISK: false 时全部不落盘
- 目录：按 SERIES_GROUP 规则（auto/series/off，见 user-config.md）——auto（默认）从会议主题提取稳定系列名（去日期词/序号词：产品周例会/技术评审/客户会议），提取到则 `{DIR}/meetings/{系列名}/`；未提取到回退 `{DIR}/meetings/YYYY-MM/` 月份平铺（DIR 按系统取 DIR_MAC/DIR_WIN，不存在回退用户主目录下 reports）；目录已存在直接复用，只覆盖本清单内同名文件；目录内存在非本 skill 命名的其它文件时对话中提示用户「该目录内已有其它文件，本次会议纪要已与它们并列存放，未做任何改动」
- 系列名落盘确认时报给用户（「本次归入系列目录『产品周例会/』」），用户可改口：说「这个系列叫 XX」→ 当次用新名建目录；说「以后这个系列叫 XX」→ 永久记住该系列名（写入 user-config.md 的 SERIES_GROUP 注释旁，后续同主题会议沿用）；系列目录名清洗：非法字符 / \ : * ? " < > | 替换为 -，首尾空格去掉
- 一次性整理指令：用户说「把我旧纪要按系列整理」→ 扫 `{DIR}/meetings/` 下全部 `meeting-minutes-*` 文件（含月份平铺目录内与已建系列目录内的）→ 从文件名 slug 或读 md 头部主题提取系列名 → 列移动计划（从哪 → 到哪，md/txt/html/png 全套）AskUserQuestion 确认 → 移动归置 → 报告三段式：✅ 已整理清单 / ⚠️ 无法归类留在原地的清单 / 🟡 失败项原因；移动后不删空月份目录（留给用户自行处置）；整理只移动不改内容
- 对话中照常输出 md 正文（不受 FORMATS 影响）；OPEN_HTML: true 且落盘了 html 时自动打开浏览器（macOS：open <html文件>；Windows PowerShell：Start-Process <html文件>）
- FORMATS 含 content-png 时生成内容区截图：只截五张分节卡片整体（会议信息/会议结论/议题讨论/决议与行动项/下次会议，不含头部标题区/复制按钮/页脚，四周保留对称合适的外边距约 40px 留白）；html 内置 `?shot=content` 参数（页面 JS 检测后隐藏 header-card/footer、body 四周 padding 统一 40px，正常浏览不受影响）；用 Chrome headless 访问带参 URL 截图（路径按系统选：macOS=`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；Windows 按序探测 `C:\Program Files\Google\Chrome\Application\chrome.exe` → `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe` → `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`，经 node child_process 执行 `--headless --disable-gpu --no-sandbox --hide-scrollbars --user-data-dir=<临时目录> --screenshot=<png路径> --window-size=760,<估算高度> --virtual-time-budget=4000 "file:///<html路径>?shot=content"`（Windows 下 URL 写作 file:///C:/...，用 node url.pathToFileURL 生成），跑完删除临时目录；禁止用 `--headless=new`（单例模式会静默失败生成占位图）；若 Chrome 不存在则换 Edge，都找不到时跳过截图并在对话注明）；高度估算基准（760 宽窄窗实测：信息头 6 行 → 议题 3 卡 → 行动项 5 行表 → 下次会议卡 → 内容区约 1650px，图高 = 内容区 + 上下留白各 40px）：每增减 1 个议题卡 ±~90、1 行行动项 ±~46、1 项决策 ±~34、信息头每多一行 ±~26；实测高度显著高于按 65~70px/条的旧估算，禁止低估导致截断，截图后用 Read 校验：五张卡片整体完整在图内、无头部/按钮/页脚残留、四周留白对称合适、不截断；底部留白过大减高度、截断加高度重截

## HTML 会议纪要版式要点（基于 reference.html）

- 头部卡片：标题「{主题}会议纪要」（主题缺失则「{日期} 会议纪要」）+ 副标题（日期 + 周几 + 起止时间 + 地点，未知项省略）+ 类型徽章（周例会/项目评审/复盘会等，按会议类型词典取词）
- 信息头节（sec-info）：两列网格（.info-grid：左列 11px muted 标签 时间/地点/主持人/参会人，右列 13px 正文；参会人用 12px chips 胶囊横排，其余值纯文本）；无内容行省略
- 复制按钮（.copy-wrap）：位于头部卡片内（标题/副标题/类型徽章之后），与日报/周报/月报/季报/年报同款「卡片内一键复制」，青色渐变胶囊居中
- 结论节（sec-sum）：一句话 TL;DR 引言行（同报表族 .tldr-line）+ 核心决策 2-5 条（.decision-row：青色小圆点 + 决策文案 14.5px）
- 议题节（sec-top）：议题卡 3-8 张（.topic-card：议题名 15px 加粗 accent 色 + 结论行「结论：」badge 样式（已决：淡青底青字；未决：淡橙底橙字）+ 讨论要点 12.5px muted 每行以青点引导）
- 行动项节（sec-act）：三列表格（.act-table：表头 事项/负责人/截止时间/状态 11px muted；行动项行 13.5px；负责人 .owner 胶囊（「待定」橙色胶囊）；截止时间 12.5px 等宽；状态徽章 .st：已完成 --green 绿底、进行中 --accent 青底、待办 muted 灰底）；行数 3-10，超 10 行拆两组或合并
- 下次会议节（sec-next）：信息行（时间 + 主题 + 地点，用 .next-line 与 muted 标签列）；均未知写「待定」
- 页脚 10px muted 文字，署名固定 GENERATED BY AI TEAM · <日期>
- 五段分节列表，条目保持中文顿号序号；md/txt 版同条目依次写，文本格式不变
