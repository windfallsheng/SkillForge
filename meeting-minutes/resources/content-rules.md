# 内容规则（五段式）

五段式骨架行业无关（任何行业、任何类型会议通用），要素侧重与行动项模板由会议类型词典适配。

## 会议要素提取

- 会议日期：优先用户口述（今天的会/昨天的会/上周三的会 → 按当前系统日期换算）；口述未明确时从材料（文件名/文件头/图片中的日期）提取；都无则问用户一句「会议是哪天开的」再生成
- 会议主题：用户口述或材料标题；无主题时按议题概括（如「XX 项目进度协调会」）
- 会议类型：话术含类型词（周例会/评审/复盘/客户会等）→ 按类型词典取要素侧重；未提 → 按 ROLE 画像推断最可能类型；推断不出 → 通用模板
- 地点/主持人/参会人：口述或材料中有则写全，缺失项写「未提及」；参会人按材料中的姓名如实列，不编造
- 文件名/目录用会议日期：见 `resources/disk-and-html.md`

## 段结构

**段一 会议信息**
- 主题 + 日期（精确到日）+ 时间（有则写）+ 地点（有则写）+ 主持人（有则写）+ 参会人（有则列）

**段二 会议结论**
- 一句话 TL;DR：这次会议拍板的核心结论（如「双周聚合发布节奏正式确认，单批 ≤6 版本，11-25 前完成验证前置改造」）
- 核心决策 2-5 项：会上明确的决定（定方案/定时间/定指标/定分工），每条一句话

**段三 议题讨论**
- 按议题逐个写：议题名 + 结论（该议题达成的共识或决定，未决则写「未决」+ 待办去向）+ 讨论要点 2-4 条（各方观点与关键事实，去口语、留数字）
- 议题 3-8 个为宜；口头闲聊/寒暄不写

**段四 决议与行动项**
- 每项三要素：事项（做什么，动词开头）+ 负责人（@某人或「待定」）+ 截止时间（YYYY-MM-DD 或「待定」）
- 负责人/截止时间缺失时写「待定」并在对话末尾提示用户补充，不编造
- 按截止时间先后排序；本段是汇报链源头——日报/周报/月报/季报生成时直接引用本纪要行动项

**段五 下次会议**
- 时间（如 2026-11-18 周三 14:00）+ 主题 + 地点（有则写）；均未知写「待定」

## 写作风格

- 中文顿号序号（1、2、3），段内条目数按上述区间；不足处写「暂无」
- 去口语化：删除「嗯/那个/然后」等口头词，保留事实、数字与结论；发言要点改第三人称陈述句
- 结论先行：每个议题先给结论再给讨论过程；数字与时间原样保留
- 客观中立：纪要不是总结，不掺入生成者评价；不同意见并列呈现，不偏袒
- 五问自检：①议题是否逐条有结论？②行动项是否三要素齐全？③数字与时间是否如实？④口语是否去净？⑤不同意见是否都记了？任一不过，改写后再输出
- md/txt 正文含生成时间行（精确到时分秒，如 2026-11-12 19:10:38）

## 素材来源

- 会话口述：用户直接口述会议过程（「会上说了三件事…」）逐条记录
- 文字材料：用户贴的会议文字/聊天记录，按五段归类
- 文件：md/txt 直接 Read 文本；docx/pdf 优先尝试 pandoc 转文本（无 pandoc 则请用户粘贴文字）；录音/视频文件不能直接解析——提示用户提供转写文本，或引导用户口述要点
- 图片：逐张 Read 识别（会议白板/聊天截图/议程照片），提取会议要素与议题；图片模糊/内容读不清时：先把已提取部分展示给用户确认或补充，不瞎编没读到的内容
- DATA_SOURCES 清单中 type: file 的文件 Read 全文、目录逐个 Read 文本文件提取要点（二进制跳过、路径无效静默跳过）；未知 type 忽略该项并在生成时提示
- 素材不足的段写「暂无」并提示用户可补充素材

## 纯文字模式与汇报链联动

- 纯文字/图片/文件整理模式：用户提供什么用什么，按五段结构归类
- 汇报链联动：本纪要的行动项是日报/周报/月报/季报的任务素材源头——生成日报等报表时，若 DATA_SOURCES 或用户素材中含会议纪要文件，其行动项可直接列为任务/进度来源；反之，生成纪要时可引用已有报表中的进度数据作为议题事实依据
- 同一会议重复生成默认覆盖；说「保留之前的/另存」→ 文件名追加时间戳
